# TD12 — Tenant Domain লাইভ যাচাই Checklist

তারিখ: 2026-10-16 · প্যাকেজ: Tenant Domain (TD1–TD12), Batch TB5 · সূত্র: `Tenant-Domain-Plan-2026-10-15.md` §TD12।

**এই নথির অবস্থা: সব আইটেম UNCHECKED।** TD প্যাকেজের প্রতিটা ফিচারের প্রমাণ এখন পর্যন্ত spec/build/fixture স্তরের (TB1–TB5 acceptance দ্রষ্টব্য) — লাইভে DNS, Cloudflare, Dokploy, আসল ডোমেইন বা আসল DB-র কোনোটাই এখনো ছোঁয়া হয়নি। এই checklist-এর কোনো বাক্স তখনই টিক দেওয়া যাবে যখন সংশ্লিষ্ট প্রমাণ (স্ক্রিনশট / probe আউটপুট / লাইভ পর্দার অবস্থা) হাতে থাকবে — প্রত্যাশা লিখে টিক দেওয়া যাবে না।

শব্দচিহ্ন: **[মালিক]** = মালিক প্যানেলে/ব্রাউজারে করবেন · **[Muse যাচাই]** = Muse বাইরে থেকে probe করে প্রমাণ দেবে · **[দুজনে]** = মালিক ধাপ চালাবেন, Muse সঙ্গে সঙ্গে যাচাই করবে।

সঙ্গী নথি: `docs/td-tb2-wildcard-runbook.md` (wildcard DNS/SSL/routing ধাপ ও ৫ probe), `docs/td-tb4-ssl-runbook.md` (Cloudflare for SaaS ধাপ ও origin-leg টেস্ট-ম্যাট্রিক্স), `docs/td-tb4-ssl-spike.md` (TD10 রায়ের গবেষণা)।

## পূর্বশর্ত (সব session-এর আগে)

- [ ] TD কোড (TB1–TB5) মালিকের নির্দেশে GitHub-এ push হয়েছে এবং Dokploy Redeploy সম্পন্ন — লাইভ API/web নতুন build-এ চলছে **[মালিক]**
  - প্রমাণ: লাইভে `GET /organizations/slug-available?slug=probe` উত্তর দেয়; web-এ onboarding পর্দায় subdomain বাছাই ক্ষেত্র দেখা যায়।
- [ ] এই checklist-এর জন্য অন্তত দুটো আসল org প্রস্তুত: (ক) পণ্যসহ চালু দোকানওয়ালা একটি বিদ্যমান org, (খ) একটি ফেলে-দেওয়ার মতো (throwaway) org — S3-এর cooldown প্রমাণের জন্য **[মালিক]**
- [ ] মালিকের Cloudflare প্যানেল অ্যাক্সেস হাতে আছে (S1, S6) **[মালিক]**
- [ ] লাইভ টেস্টের স্পেয়ার আসল ডোমেইন হাতে আছে (প্ল্যানের D3 সিদ্ধান্ত) — না থাকলে S5/S6 চলবে না, বাকি session চলতে পারে **[মালিক]**

## S1 — Wildcard রানবুকের ধাপ + ৫টি probe (TD3)

সূত্র: `docs/td-tb2-wildcard-runbook.md` ধাপ ০–৪ হুবহু।

- [ ] **ধাপ ১:** Cloudflare-এ wildcard `*` A রেকর্ড বসেছে — মান বিদ্যমান `app` রেকর্ডের হুবহু কপি, Proxied, TTL Auto **[মালিক]**
  - প্রমাণ: Cloudflare DNS পর্দার স্ক্রিনশট (রেকর্ডের Type/Name/মান/Proxy অবস্থা দেখা যাচ্ছে)।
- [ ] **ধাপ ২ক:** SSL/TLS মোড **Full (Strict)** যাচাই হয়েছে; Edge Certificates-এ Universal SSL সক্রিয় ও `*.qosprey.com` আওতাভুক্ত **[মালিক]**
  - প্রমাণ: দুই পর্দার স্ক্রিনশট।
- [ ] **ধাপ ২খ:** Origin wildcard সার্টিফিকেটের পথ (Origin CA পথ A / ACME DNS-01 পথ B) — কোনটা নেওয়া হলো রানবুকে টীকা দিয়ে রাখা হয়েছে **[মালিক]**
  - প্রমাণ: রানবুকের টীকা + সার্টিফিকেটের মেয়াদ/নাম পর্দা (private key কখনোই নয়)।
- [ ] **ধাপ ৩:** Wildcard routing (Dokploy Domains পথ A / Traefik dynamic config পথ B) চালু; কোন পথ নেওয়া হলো রানবুকে টীকা; একটা Dokploy Redeploy-এর পরেও routing টিকে আছে কিনা যাচাই হয়েছে **[মালিক + Muse যাচাই]**
  - প্রমাণ: Redeploy-এর পর probe ১ আবার চালিয়ে একই ফল।
- [ ] **Probe ১ — এলোমেলো subdomain পৌঁছায়:** `probe-<এলোমেলো>.qosprey.com` DNS resolve হয়, web অ্যাপ উত্তর দেয় (org নেই বলে দোকানের 404 আচরণই প্রত্যাশিত) **[Muse যাচাই]**
  - প্রমাণ: probe-এর HTTP status + উত্তরের সারাংশ acceptance-এ কপি।
- [ ] **Probe ২ — বিদ্যমান সেবা অক্ষত:** `qosprey.com`, `app`, `admin` আগের মতো পেজ দেয়; `api.qosprey.com/health` 200 JSON; `media` আগের আচরণে **[Muse যাচাই]**
  - প্রমাণ: প্রতিটা হোস্টের status সারি।
- [ ] **Probe ৩ — আসল org-এর দোকান:** বিদ্যমান org-এর slug দিয়ে `{slug}.qosprey.com` খুললে দোকানের হোম পেজ পণ্যসহ আসে **[Muse যাচাই]** (বিস্তারিত S2-তে)
- [ ] **Probe ৪ — TD5 redirect:** একই subdomain-এ `/dashboard` → **308** → `https://app.qosprey.com/dashboard` **[Muse যাচাই]** (বিস্তারিত S4-তে)
- [ ] **Probe ৫ — SSL:** `{slug}.qosprey.com`-এ ব্রাউজারে সার্টিফিকেট সতর্কতা নেই; সার্টিফিকেটের নাম `*.qosprey.com` আওতার **[Muse যাচাই]**
  - প্রমাণ: ব্রাউজারের সার্টিফিকেট পর্দার স্ক্রিনশট বা `curl -v` হ্যান্ডশেক সারাংশ।

## S2 — আসল org subdomain-এ দোকানের পথ (TD4)

- [ ] **হোম পেজ:** `{slug}.qosprey.com/` — ওই org-এরই দোকান (নাম/লোগো/থিম তার নিজের), পণ্যের তালিকা আসল **[মালিক ব্রাউজারে + Muse যাচাই]**
  - প্রমাণ: স্ক্রিনশট; পাশাপাশি `app.qosprey.com/shop/{slug}` পথের পেজের সাথে একই দোকান কিনা মিলিয়ে দেখা।
- [ ] **পণ্যের পেজ:** হোম থেকে একটা পণ্যে ক্লিক — পণ্যের বিস্তারিত পেজ subdomain-এর ঠিকানাতেই খোলে, ছবি/দাম/স্টক ঠিক **[মালিক]**
- [ ] **কার্ট:** পণ্য কার্টে যোগ হয়; কার্ট পেজ subdomain-এই চলে **[মালিক]**
- [ ] **চেকআউট পথ:** চেকআউট ফর্ম পর্যন্ত যাওয়া যায়; পরীক্ষামূলক অর্ডার (COD) দিলে success পেজ আসে এবং অর্ডারটা ওই org-এর ড্যাশবোর্ডে দেখা যায় **[মালিক]**
  - প্রমাণ: success পেজের স্ক্রিনশট + ড্যাশবোর্ডে অর্ডারের স্ক্রিনশট (একই অর্ডার নম্বর)।
- [ ] **দোকান বন্ধ থাকলে সৎ আচরণ:** `shopEnabled` বন্ধ থাকা org-এর subdomain-এ দোকান খোলে না (বিদ্যমান storefront আচরণই) **[Muse যাচাই]**
- [ ] **অস্তিত্বহীন slug:** `{এলোমেলো-নাম}.qosprey.com` — 404 আচরণ, অন্যের দোকান বা প্ল্যাটফর্ম পেজ খোলে না **[Muse যাচাই]**
  - প্রমাণ: HTTP status + পেজের সারাংশ। (এই tree-তে branded shop 404 নেই — Next ডিফল্ট 404-ই প্রত্যাশিত; TB2 acceptance-এর নথিভুক্ত অমিল।)

## S3 — Slug শাসনের লাইভ প্রমাণ (TD1 + TD11)

Onboarding পর্দায় (আসল অ্যাকাউন্টে নতুন org তৈরির ধাপে) একে একে চেষ্টা:

- [ ] **`dashboard`** — সংরক্ষিত বলে কারণসহ প্রত্যাখ্যান (লাইভ যাচাই বাক্সে বাংলায় কারণ দেখা যায়, submit নিষ্ক্রিয়) **[মালিক]**
- [ ] **`fake`** — একই প্রত্যাখ্যান **[মালিক]**
- [ ] **`orgnail`** — একই প্রত্যাখ্যান **[মালিক]**
- [ ] **Substring কেস:** `my-admin-shop` ও `supportbd` — শব্দাংশ-নিয়মে প্রত্যাখ্যান **[মালিক]**
- [ ] **API দিয়েও ফাঁকি হয় না:** সরাসরি `POST /organizations`-এ `slug: "dashboard"` পাঠালে সার্ভার একই কারণে BadRequest দেয় (শুধু UI যাচাই নয়) **[Muse যাচাই]**
  - প্রমাণ: অনুরোধ/উত্তরের সারাংশ (status + বার্তা)।
- [ ] **নেওয়া নাম:** বিদ্যমান org-এর slug আবার নিতে গেলে "taken" কারণ আলাদা করে বোঝা যায় **[মালিক]**
- [ ] **সাধারণ নাম চলে:** একটা নির্দোষ নতুন নাম (যেমন throwaway org-এর জন্য) কোনো বাধা ছাড়া তৈরি হয় **[মালিক]**
- [ ] **TD11 cooldown লাইভ প্রমাণ:** throwaway org-টা soft-delete → admin থেকে permanent delete করার পর, একই slug দিয়ে নতুন org বানাতে গেলে **cooldown** কারণ ও মুক্তির তারিখসহ প্রত্যাখ্যান আসে; `slug-available` endpoint-ও একই রায় দেয় **[দুজনে]**
  - প্রমাণ: permanent delete-এর উত্তর (`slugTombstoneWritten: true` থাকা), তারপর picker পর্দায় cooldown বার্তার স্ক্রিনশট + endpoint উত্তরের সারাংশ।
- [ ] **SUPER মুক্তির লাইভ প্রমাণ:** admin Orgs পর্দার Slug Cooldown কার্ডে ওই নামটা দেখা যায়; কারণ লিখে "মুক্ত করুন" চাপলে নামটা আবার খালি হয় এবং ওই slug দিয়ে org তৈরি চলে **[মালিক]**
  - প্রমাণ: কার্ডের আগে/পরের স্ক্রিনশট + audit লগে `admin.slug_tombstone_released` সারি।

## S4 — TD5 surface পৃথকীকরণের লাইভ প্রমাণ

- [ ] **`/dashboard`:** `{slug}.qosprey.com/dashboard` → 308 → `https://app.qosprey.com/dashboard` **[Muse যাচাই]**
  - প্রমাণ: `curl -I` বা ব্রাউজার network পর্দায় status 308 + Location হেডার হুবহু।
- [ ] **`/login` ও `/register`:** একই redirect আচরণ **[Muse যাচাই]**
- [ ] **`/accept-invite?token=…`:** আসল আমন্ত্রণ লিংকের token-সহ subdomain ঠিকানায় খুললে token **অক্ষত** অবস্থায় app ডোমেইনে redirect হয় এবং আমন্ত্রণ গ্রহণের পর্দা ঠিকমতো আসে **[মালিক]**
  - প্রমাণ: redirect-এর পরের URL (token-সহ) + পর্দার স্ক্রিনশট। টোকেন এই checklist-এ লেখা যাবে না — স্ক্রিনশটে টোকেন ঝাপসা করে দিতে হবে।
- [ ] **Custom domain হোস্টেও একই:** যাচাই করা custom domain-এ `/dashboard` খুললেও একই 308 app ডোমেইনে **[Muse যাচাই]** (S5-এর ডোমেইন তৈরি হওয়ার পর)
- [ ] **"দোকান পরিচালনা করুন" লিংক:** দোকানের header-এর লিংক `https://app.qosprey.com`-এ নিয়ে যায় **[মালিক]**
- [ ] **প্ল্যাটফর্ম হোস্টে কোনো বদল নয়:** `app.qosprey.com/dashboard` সরাসরি আগের মতোই চলে (redirect লুপ নেই) **[Muse যাচাই]**

## S5 — Custom domain সম্পূর্ণ যাত্রা (TD9) — আসল স্পেয়ার ডোমেইন দিয়ে

পূর্বশর্তের স্পেয়ার ডোমেইন একটা আসল org-এ বসিয়ে, storefront settings-এর "নিজের ডোমেইন" বিভাগ ধরে:

- [ ] **ধাপ ১ — ডোমেইন সেভ:** ডোমেইন লিখে সেভ হয়; অবস্থা তালিকায় "টোকেন দেওয়া হয়নি" অবস্থা সৎভাবে দেখায় **[মালিক]**
- [ ] **ধাপ ২ — TXT যাচাই:** টোকেন তৈরি → `_qosprey-verify.<domain>`-এ TXT বসানো → "যাচাই করুন" চাপলে আসল DNS lookup-এ **verified** হয়; verified হওয়ার আগের চেষ্টায় সৎ ব্যর্থতা দেখায় **[দুজনে]**
  - প্রমাণ: DNS পর্দার স্ক্রিনশট (টোকেনের মান দেখা যাবে — এটি পাবলিক DNS রেকর্ডই) + verified অবস্থার স্ক্রিনশট।
- [ ] **ধাপ ৩ — Routing:** UI-এর নির্দেশ মতো CNAME/flattening বসানোর পর routing diagnostic **active** বলে; তার আগে চালালে "এখনো পৌঁছায়নি" ধরনের সৎ ফল দেয় **[দুজনে]**
- [ ] **দোকান লাইভ (HTTP স্তরে):** `https://<domain>/` খুললে ওই org-এর দোকানই root-এ আসে (SSL অংশ S6-তে; সার্টিফিকেট সতর্কতা এলে এখানে টিক নয়, S6-তে যাবে) **[মালিক]**
- [ ] **www রূপ:** `https://www.<domain>/`-ও একই দোকানে resolve হয়; উল্টোটাও — ডোমেইন www-রূপে সেভ করা থাকলে apex রূপটাও চলে **[Muse যাচাই]**
  - প্রমাণ: দুই হোস্টের উত্তরের সারাংশ (একই org slug)।
- [ ] **প্ল্যাটফর্ম ডোমেইন প্রত্যাখ্যান:** সেভে `something.qosprey.com` লিখলে সার্ভার কারণসহ প্রত্যাখ্যান করে **[মালিক]**
- [ ] **ডোমেইন বদলে যাচাই রিসেট (TB4-এ ধরা বাগের লাইভ প্রমাণ):** verified অবস্থায় ডোমেইন বদলে অন্য নাম সেভ করলে নতুন ডোমেইন **unverified** অবস্থায় থাকে — পুরনো TXT প্রমাণে নতুন নাম resolve হয় না; `by-domain` নতুন নামে NotFound দেয় **[দুজনে]**
  - প্রমাণ: বদলের পরের অবস্থা তালিকার স্ক্রিনশট + by-domain probe-এর উত্তর।
- [ ] **ডোমেইন সরানো:** "ডোমেইন সরিয়ে ফেলুন" → দোকান আবার শুধু subdomain ঠিকানায়; পুরনো ডোমেইন আর resolve হয় না **[মালিক + Muse যাচাই]**

## S6 — Cloudflare for SaaS টেস্ট-ম্যাট্রিক্স ও SSL সাফল্যের মাপকাঠি (TD10)

সূত্র: `docs/td-tb4-ssl-runbook.md` ধাপ ০–৩ হুবহু; রায়: Cloudflare for SaaS (শর্তসাপেক্ষ)।

- [ ] **ধাপ ১:** for SaaS enable + fallback origin মনোনয়ন (কোন রেকর্ড, রানবুকে টীকা) + status Active **[মালিক]**
- [ ] **টেস্ট (i) — যেমন আছে Full (Strict):** স্পেয়ার ডোমেইনের custom hostname তৈরি (delegated DCV-সহ) → hostname ও `ssl.status` দুটোই active; ব্রাউজারে ডোমেইন খোলে; Cloudflare **526 আসে না** **[দুজনে]**
  - প্রমাণ: Custom Hostnames পর্দার স্ক্রিনশট (status দুটো) + ব্রাউজারে দোকান খোলার স্ক্রিনশট।
- [ ] **টেস্ট (ii) — (i) ব্যর্থ হলে:** প্রতি hostname-এ `custom_origin_server` = wildcard-আওতার proxied নাম — handshake চলে কিনা, Full (Strict) আচরণ **[দুজনে]**
- [ ] **টেস্ট (iii) — (i)/(ii) ব্যর্থ হলে:** hostname-ভিত্তিক configuration rule-এ শুধু custom ট্র্যাফিকে মোড ছাড় — platform হোস্টগুলোর Full (Strict) অক্ষত থাকার প্রমাণসহ; **ছাড়ের সিদ্ধান্ত মালিকের** (রানবুকের সতর্কতা) **[মালিক সিদ্ধান্ত + Muse যাচাই]**
- [ ] **কোন বিন্যাস চলল** রানবুকে টীকা দিয়ে রাখা হয়েছে **[মালিক]**
- [ ] **Apex পরীক্ষা:** স্পেয়ার ডোমেইন apex হলে CNAME flattening দিয়ে SaaS target-এ validate/active হয় **[Muse যাচাই]**
- [ ] **🎯 TD10-এর সাফল্যের মাপকাঠি:** একদম নতুন একটা verified ডোমেইন (দ্বিতীয় টেস্ট ডোমেইন বা একই ডোমেইন নতুন org-এ) **কোনো সার্ভার-হাত ছাড়াই** HTTPS-এ দোকান দেখায় — সার্টিফিকেট সতর্কতা ছাড়া **[দুজনে]**
  - প্রমাণ: ব্রাউজারে পূর্ণ পেজ + সার্টিফিকেট পর্দা (ইস্যুকারী Cloudflare, নাম ডোমেইনের সাথে মিল)।
- [ ] **Platform অক্ষত:** টেস্টের পরে app/admin/api/media + tenant subdomain আগের আচরণে; কোনো মোড-ছাড় platform হোস্টে লাগেনি **[Muse যাচাই]**
