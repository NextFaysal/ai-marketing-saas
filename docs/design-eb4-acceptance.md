### Worker rule table

| Request | Handling |
|---|---|
| Non-GET (any) | Never intercepted |
| `/backend/*`, `/api/*` | Never intercepted (auth/cart/order traffic stays live) |
| Media CDN host (`media.qosprey.com`, derived from `MEDIA_CDN_BASE_URL`) | Cache-first in `shop-media-v2`; opaque no-cors responses cache too; bounded — see below |
| Other cross-origin | Never intercepted |
| `/shop-push-sw` (own script) | Never intercepted |
| Same-origin `/_next/static/*` + font files (`.woff/woff2/ttf/otf`) | Cache-first in `shop-static-v2` (content-hashed/versioned URLs) |
| Navigation (`mode: navigate`) outside `/shop/*` | Never intercepted |
| Navigation to transactional paths — `/(cart\|checkout\|account\|success)/` segments, `/track/*` | Never intercepted: network only, **no cache writes** (`success` is a deliberate superset of the brief's list — an order summary must never be replayed from cache) |
| Other `/shop/*` navigation | **Network-first**: a successful (ok) response is copied to `shop-pages-v2`; on network failure serve (1) the cached copy of that exact URL, else (2) the cached shop home for the URL's org segment (query-insensitive — a filtered home beats the generic page), else (3) the offline fallback |
| Anything else | Never intercepted |

**Cache bounds + versioning.** Page cache capped at
**30 entries**, media cache at **60 entries**; eviction is
oldest-first (Cache Storage keys are insertion-ordered;
`trimCache` deletes from the front — spec-pinned). Static cache
is bounded by versioning instead of count (hashed asset URLs).
`SHOP_SW_VERSION = "2"` names all three caches
(`shop-static-v2` / `shop-pages-v2` / `shop-media-v2`); the
activate handler purges **only** `shop-*` caches outside the
current set (spec-pinned, and the script never names the
dashboard worker's caches — they share this origin's Cache
Storage and are not this worker's to delete), then
`clients.claim()`. Install precaches the offline page into the
static cache and `skipWaiting()`s; a failed precache (installed
while already offline) does not block activation.

### What a shopper actually sees offline

1. **A shop page they visited before** → that page's cached
   copy (network-first means any successful online visit
   refreshes it).
2. **A shop page they never visited, in a shop they did** →
   the cached shop home for that org.
3. **Anything else under /shop/** → the **generic offline page**
   (`/shop/offline`, precached at install): a static,
   zero-network, platform-neutral page — 📡, "ইন্টারনেট সংযোগ
   নেই" + the bn dictionary text, the en title/text under it,
   and one retry button (`আবার চেষ্টা করুন · Try again`) that
   reloads. It shows **no shop name and no platform branding**
   (it cannot know the shop — no fetch is possible or
   attempted). Routing evidence: the static `offline` segment
   wins over `[orgSlug]` (build manifest carries both routes;
   the offline page prerendered to plain HTML).
4. **Even the precached page is missing** (precache failed) →
   the worker answers with a tiny inline HTML document in the
   same bn/en copy — the last resort built into the script.

Offline copy lives in `lib/shop-i18n.ts` as the new `offline`
section (bn+en pairs; the key-set test stays green). The page
reads the pure dictionaries directly — no locale fetch exists
or is needed.

## ED11 — Micro-interactions

### Route progress bar (`components/route-progress.tsx`)

Hand-rolled, no dependency, mounted in BOTH the shop layout
(inside the shop root, so its gradient reads the org's
`--brand`) and the dashboard layout. App Router has no router
events, so the mechanism is click-capture + location-watch:

- **Start**: a capture-phase document click listener — a click
  on a same-origin `<a>` with a different path/search (not
  hash-only, not `_blank`/`download`, no modifier keys) starts
  the bar: 12% immediately, trickling toward an 85% ceiling.
- **Finish**: `usePathname` change (or `popstate`) completes
  to 100%, fades, resets.
- **Edge cases, honestly**: a **6s safety timeout** completes
  the bar if no observable change lands — the known blind spot
  is a query-only soft navigation (pathname unchanged; the bar
  may sit at its ceiling until the timeout even though the
  navigation finished sooner). Full-page navigations unload the
  document, so the bar dies with the page after a brief show.
  Clicks that open drawers/menus are same-location and never
  start it (the path/search equality check).
- **Presentation**: 3px fixed top bar, brand gradient,
  `pointer-events-none`, **z-[45]** — chosen against the actual
  scale in use: sticky headers z-20/30, dashboard topbar z-40,
  shop dialogs z-50, @repo/ui Modal/Drawer z-[80], toasts
  z-[90]. Above content, below every modal/drawer.
- `useSearchParams` was deliberately NOT used (it would force
  a CSR bailout up to the nearest Suspense boundary on shop
  pages); pathname + popstate + the safety timeout cover the
  observable cases.

### Add-to-cart badge bump

- `globals.css`: `@keyframes badge-bump` (scale 1 → 1.35 → 1)
  + `.badge-bump` running it over `--motion-slow`.
- Logic in `lib/use-badge-bump.ts`: the pure predicate
  `shouldBumpBadge(prev, next)` (spec-pinned: bump **only** on
  a strict increase over a known previous count — never on
  first observation, decrease, or repeat) and the
  `useBadgeBump(count)` hook returning a bump key; the badge
  span is keyed by it with the class applied only when key > 0,
  so the pulse replays exactly once per increase. Wired into
  **ShopHeader** (v2 + legacy cart badges) and **ShopBottomNav**
  (cart badge) — the counts themselves still come from the EB2
  header cache + `CART_UPDATED_EVENT` flow; the hook adds **no
  fetches**.
- **No drawer auto-open** (documented choice, per brief):
  opening the cart drawer on every add is obtrusive
  mid-browsing; the bump is the whole feedback.

## Honest limits

- **Service-worker behaviour is spec-proven, not
  browser-proven.** No deployed origin + real browser pass
  exists in this sandbox: cache hits, the install/activate
  lifecycle, and the offline fallbacks are pinned by string
  specs over the generated script and the green production
  build, not by observing a worker run. Screenshot/live QA
  remains post-deploy (the EB3 checklist pattern).
- **Registration reality (pre-existing, unchanged by design)**:
  the shop worker registers only when a shopper subscribes to
  push (ShopPushPrompt / push-panel) — so the ED10 shell is
  active for those shoppers today. Everyone else's shop visits
  remain under the dashboard worker (root scope), whose page
  cache + `/offline` fallback behave exactly as before; the
  dashboard worker's behaviour was NOT touched. Registering
  the shop worker eagerly for all shop visitors would change
  AB7's consent posture and was outside this batch's mandate
  ("registration must not need changes") — flagged here as the
  obvious follow-up decision for the owner.
- The precached offline page is a Next HTML document: served
  from cache it renders its static content with zero network;
  its client JS (the retry island) comes from the static cache
  only if those hashed chunks were cached by an earlier visit —
  if not, the text still renders and the button is inert until
  any page load succeeds (the worker's inline-HTML last resort
  covers the precache-missing case with a working reload
  button).
- Cached shop pages are network-first snapshots: prices/stock
  in an offline-served copy are as old as the last successful
  visit (the same honesty bound as any app shell; transactional
  pages are never cached at all).
- RouteProgress's query-only blind spot is documented above
  (6s ceiling); RouteProgress itself ships without a unit spec
  — its logic is DOM/timing-bound and the batch pinned the
  testable predicates (badge bump, worker script) instead.
- ShopInstallBar timing/queue behaviour is re-verified by zero
  diff, not re-specced in this batch.
- Nothing is deployed or live-proven; deploy still needs the
  owner's push instruction + Dokploy Redeploy, outside this
  batch. When it deploys, existing push subscribers' workers
  update to SHOP_SW_VERSION 2 on the next worker update check
  (the route serves `Cache-Control: no-cache`).
