   SU added `healthCheckedAt` + three relations (`postingSlots`,
   `autoDraftConfigs`, `followerSnapshots`); CC-Advanced added
   `providerHealth`/`providerHealthAt`/`providerHealthError` (CC15)
   + `label`/`groupName` (CC17). The hunk also swallowed the SU7
   `SocialAccountFollowerSnapshot` model and the `SocialPostGroup`
   header into its span. Resolution: the model was rebuilt as the
   exact union (all fields, all four relations, `@@unique` + `@@index`
   both kept); the follower-snapshot model and `SocialPostGroup`
   (header + its auto-merged tail) verified byte-intact against the
   SU branch.
2. **`apps/api/src/social/social.service.ts` — imports.** Union:
   SU's `Optional` import + CC's `isConnectionDenied` import.
3. **`apps/api/src/social/social.service.ts` — create path.** SU had
   refactored creation into `validatePostVariant` + `createPostRow`;
   CC17 had put its deny-guard (`assertAccountAccess`) inside its own
   monolithic `createPost`. Resolution: CC's `assertAccountAccess`
   method kept verbatim; `validatePostVariant` gained an `actorId`
   parameter and calls the guard right after the account lookup —
   so the guard now covers `createPost`, `createPostRow` AND every
   `createPostGroup` variant (both internal callers updated). The
   CC17 call sites on the schedule/publish paths and in
   `SocialPublishService.publishNow` (via `social.assertAccountAccess`)
   survived the auto-merge untouched — deny-guard and SU health/
   approval gates are both still enforced.
4. **`apps/api/src/social/social-publish.service.ts` — constructor.**
   Both sides appended an `@Optional()` last parameter (SU6 `links`,
   CC20 `linkedinClient`) at the same positional slot. Spec evidence:
   the CC20 spec constructs the service positionally with the LinkedIn
   stub at slot 9; no SU spec passes `links` positionally (SU6 tests
   `SocialLinkService` directly; in production it is Nest-injected by
   type). Resolution: `linkedinClient` keeps slot 9, `links` goes
   last (slot 10) with its SU6 comment preserved — both spec contracts
   intact, both fields assigned in the constructor body.
5. **`apps/api/src/social/social.controller.ts` — DTO imports.**
   Union of both import lists (SU's full DTO set +
   `SelectLinkedInOrganizationDto` from CC20).
6. **`apps/api/src/automation/automation.service.ts` — job types +
   constructor.** Job-type list: SU's `social_evergreen_sweep` +
   `social_follower_snapshot` and CC12's `connection_health_sweep`
   all present. Constructor tail: SU appended `socialQueue` +
   `socialInsights` last for positional-spec safety; CC appended
   `connectionMonitor`. Resolution: SU order preserved,
   `connectionMonitor` appended after them (no spec on either line
   constructs `AutomationService` with any of the three positionally —
   verified by grep; the CC12 sweep dispatch case is present in the
   merged service).
7. **`apps/web/tsconfig.tsbuildinfo`** — tracked build artifact;
   resolved by taking HEAD's version (regenerated by every tsc run;
