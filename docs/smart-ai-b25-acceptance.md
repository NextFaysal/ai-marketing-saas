## Item 1 — AI Activity API (commit `6dbfe06e`)

`AiActivityService` + `AiActivityController` (`apps/api/src/ai/ai-activity.*`), registered in the leaf `ActionEngineModule` (the SA-B21 placement rationale: it already hosts the engine + copilot controllers and nothing imports it back). `@PermissionArea("ai")`, TenantGuard + RolesGuard, **both GETs member-level** (no `@Roles` — mirroring `listProposals`/catalog; spec-pinned via handler metadata).

- **`GET organizations/:organizationId/ai/activity?kind&days&limit&offset`** → `{ items, total, limit, offset, days, kind }`. `days` ∈ {7, 30, 90} (default 30), `kind` ∈ {proposal, learned, answer, content} (absent = all) — anything else is a 400 (service-owned validation, SA-B24 pattern); limit clamps 1..100 (default 50), offset 0..5000. Events are **expanded from real rows at real stamps**: proposal `filed` (createdAt) / `decided` (decidedAt; meta carries decision + `proposalOnly` + decidedById) / `executed` (executedAt) / `failed` (updatedAt — the terminal-stamp lens SA-B24 established — with `error` as detail, verbatim); learned `suggested` (createdAt; meta itemKind + sourceType) / `decided` (reviewedAt, status-filtered; meta decision + **`reviewedVia` carried through, null staying null** + appliedRef); answer `captured` (createdAt; meta channel/origin/hitCount) / `invalidated` (updatedAt; detail = `invalidReason` verbatim); content `draft_created` (SocialPost rows with `autoDraftKind = "ai_content"`; meta autoDraftRef + status). Proposal `filed` meta also carries `via` from `sourceRef`, so a copilot-filed proposal is recognisable as one. Each source is fetched with its own stamp-ordered query at `take = offset + limit` (an event in the global page provably sits inside its own source's top `offset + limit`, so merged paging is exact), merged, sorted `at` desc (id-desc tie-break), sliced; `total` is the **exact** event count from per-source `count` queries — not the page size, not an estimate.
- **`GET organizations/:organizationId/ai/activity/usage?days=7|30`** (default 30; else 400) → `{ days, since, totals, features, daily }` aggregated in code from the org's `AIUsageRecord` rows in the window (the SA-B24 pattern): totals {calls, inputTokens, outputTokens, estimatedCalls}; per-feature rows sorted calls desc (feature asc tie-break) with the `estimated` count kept separate and visible; `daily` ascending by UTC date listing **only days that actually have calls** — no zero-filled days are fabricated to complete a chart.

## NOT BUILT (explicit)

- **Auto-filing failures into the learning queue** — the plan's "ভুলের লগ → শেখার queue" arrow as an automatic loop (see Step 0.4). The feed IS the mistake log (failed proposals + invalidated answers, reasons verbatim, inside the same settings page as the queue); turning execution errors into LearnedItem suggestions is a new learning path that would need the mining discipline (PII screen, grounding, dedupe), not a close-out wiring task. Not built, not implied anywhere in the UI.
- **A copilot Q&A history store** — SA-B21's statelessness stands. The copilot's T4 activity record is what genuinely persists: the proposals it files (in the feed, badged by `via`) and its usage bucket (in the overview). Persisting owners' questions is a data-retention decision for the owner, not something a close-out batch smuggles in.
- **Per-hit answer events** — impossible honestly: no per-hit log exists (SA-B24). Hits surface as the cumulative counter they are (Brain overview + the `captured` event's meta), never as a fabricated event stream.
- **Feed rows for audit-log-only acts** (answer-store enable/disable transitions, memory forgets) — those live on their SA-B6 surfaces with their own audit trail; the T4 feed covers the four row-backed kinds and does not mirror the audit table.
- **Admin-side (platform) views of this feed** — the platform's cross-org lens is SA-B24's Oversight board (counts, no contents); a per-org admin activity feed was not in T4's tenant text and SA-B23's audited view remains the only door to a tenant's Brain contents.
- **Live verification = M30** — nothing here is live-proven: no real tenant session has exercised the Activity API or the completed section, and no migration has run on the real database (none was added).
