**(b) The Action Engine's execute path** funnels through ONE private method: `runExecution` (approve → claim → runExecution; execute → runExecution; L2 autonomous → runExecution). `execute()` already speaks the refusal shape `{ ok: false, reason, message }`.

**(c) Platform settings storage exists and is the right home:** `SystemSetting` (key/Json/updatedById) already holds the `killSwitches` row — `{ aiDisabledOrgIds: string[], broadcastsPaused: boolean }` — read everywhere through ONE helper, `killSwitches()` in `common/platform-settings.ts`, and consulted at **16 call sites** today (chat, creative studio, vision, embeddings, mining, voice, ads narration, copilot, ai-instructions, inbox, messaging ×1 of 2, social AI/coach/image, content generation, broadcast personalisation). The global flag therefore extends THAT row and THAT read path — **no migration, no second switchboard.** The generic AdminService settings validation requires only the two legacy fields' types, so the added fields pass through it untouched; the dedicated T3 endpoints below are the supported write path for the new fields (a wholesale generic-settings save would need to carry them — the same caveat any added field of that row has always had).

**(d) Aggregate-able rows that actually exist:** `AIActionProposal` (status lifecycle + `error` verbatim + `verification` + `executedAt`; engine rows carry `actionId`, legacy Milestone-47 rows carry none), `AIUsageRecord` (one row per recorded call; `feature` is the bucket — chat/report/copilot/content_generation/broadcast_personalization/…; input/output tokens + an `estimated` flag), `AiStoredAnswer` (status, cumulative `hitCount`, per-row `lastHitAt`, `invalidReason`), `LearnedItem` (status, `sourceType`, `reviewedAt`, `reviewedVia` from SA-B23). **Not persisted anywhere, therefore NOT on the board:** per-hit answer timestamps (hitCount is a counter, lastHitAt is per-row — windowed serve counts are reported as *distinct answers hit*, named as such), guard-drop counters (drops are recorded per-surface in run results, not in a platform table — no board number pretends otherwise).

## Item 2 — the global kill switch + enforcement (commit `23adf399`)

**Storage & read path.** The `killSwitches` Json gains `aiGloballyPaused: boolean`, `aiGlobalPause: { paused, reason, byId, at }` (the LAST flip's provenance — a resume records its own reason too), and `aiOrgPauseMeta: { [orgId]: { disabled, reason, byId, at } }`. `killSwitches()` returns them additively (every existing destructure is unaffected; absent = unpaused, so every pre-B24 row reads correctly), joined by the two helpers every enforcement point now consults: `isAiDisabledForOrg(ks, orgId)` (global OR per-org) and `aiPauseReason(ks, orgId)` → `"ai_globally_paused" | "ai_disabled_for_org" | null` (global outranks org).

**Flips.** Reason-first, exactly as SA-B23's fixes: a trimmed-empty reason is a 400 BEFORE any read/write/audit; a non-boolean flag is a 400; an unknown org is a 404 with no write. Writes are read-modify-write of the one row, preserving every sibling field (incl. `broadcastsPaused` and fields this service doesn't know), stamped `updatedById` = the admin. Each flip writes its audit row with the reason verbatim — `admin.ai_kill_switch_global_pause` / `_global_resume` (platform scope, no organizationId) and `admin.ai_kill_switch_org_disable` / `_org_enable` (org-scoped). Per-org disables written before this batch carry no T3 provenance: the state endpoint lists them with null reason/by/at — never invented metadata.

**Enforcement — the choke points from Step 0:**
1. **LlmFactory guard wrap** (`ai/llm/llm-guard.ts`): whenever the factory has its Prisma handle (always in the running app; a direct `new LlmFactory()` in specs stays unwrapped, byte-identical behaviour), every provider it hands out is wrapped so `complete` / `completeStream` / `completeVision` first re-read the switchboard and throw the typed **`AiPausedError`** (403, `code "AI_PAUSED"`, scope global|org) while paused. `name`/`isRealLlm` delegate live (the not-configured honesty is unchanged); optional methods are wrapped only when the inner provider implements them (no capability is made to appear). The check runs PER CALL — a flip takes effect on the next call. This is the backstop that covers factory consumers with no per-site check of their own — inbox autopilot compose is the deliberate example (SA-B7/B8 recorded it as intentionally not per-site gated). `forOrg`'s platform fallback is additionally wrapped with the org's scope.
2. **Action Engine**: `execute()` returns `{ ok: false, reason: "ai_paused", message }` (a new member of the existing refusal union) and `runExecution()` returns the row UNEXECUTED before any claim — so approve() and L2-autonomous paths queue too. Proposals may still be FILED and APPROVED while paused; a pause is never recorded as a failure; terminal/rejected/money/approval reads stay available (they execute nothing).
3. **All 16 pre-existing per-site checks** now use the combined predicate: throwing sites throw the global variant message under a global pause and the byte-identical org message under a per-org disable; the four skip-shaped surfaces return the recorded reason — conversation mining and voice learning skip per-org with `reason: "ai_globally_paused"` in their run results/LearningState (the sweeps that call them record exactly that), ads narration returns `narrationNote: "ai_globally_paused"` over a fully computed digest, embeddings `resolveConfig` returns `{ ok: false, reason: "ai_globally_paused" }` so indexing records sources unavailable rather than failed.

**The stored-answer judgement (recorded as briefed):** while paused, deterministic surfaces keep working — digests compute, and the **Answer Store still serves**. Stored answers are pre-approved, human-reviewed content (the store serves rows a person approved or a grounded compose already passed through the number guard); serving one is retrieval, not new AI generation, and pausing it would punish customers for an operator's provider incident. What stops is everything that CREATES: generation/composition (choke point 1), mining/narration/embeddings (their gates), and action execution (choke point 2). New captures into the store ride the compose paths (autopilot/suggest captures happen after an LLM compose), so nothing new is learned while paused either — the store can only serve what was already approved before the pause.
